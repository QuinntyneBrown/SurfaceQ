# Plan: `surfaceq inventory` — complete object census of an Angular target

**Status:** proposed
**Targets:** new requirements L2-031..L2-034 (trace to L1-002, L1-004, L1-013)
**Suggested version:** minor bump to `0.12.0` (additive: a new subcommand)

## Goal

A new `inventory` subcommand that produces a **complete inventory of every
developer-authored object** (classes, interfaces, enums, type aliases,
functions, constants, injection tokens) in an Angular **application**,
**library**, or **workspace** (apps + libs) — **except tests** — and writes the
result as one `INVENTORY.md` per project.

Unlike `docs` (which documents only the *exported public API* of each
`ng-package.json` library), `inventory`:

1. covers **applications too**, not just libraries;
2. lists **all** declarations, **exported and internal** (each row marked
   `Exported: yes/no`);
3. classifies each object by its **Angular role** (Component, Directive, Pipe,
   Service, NgModule, Guard, Resolver, Interceptor) in addition to its
   TypeScript kind;
4. is a **census, not a contract** — it documents *what exists and where*, not
   how to consume it. No reachability tracing, no hiding of implementations.

## Command

```
surfaceq inventory [--project <root>] [--output INVENTORY.md] [--verbosity <level>]
```

- `--project <root>` — the app, library, or workspace root. Defaults to cwd.
- `--output <path>` — path relative to **each project directory**. Default
  `INVENTORY.md`.
- Exit codes match `docs`: `0` ok, `2` error (no projects found, parse error,
  or write failure). All projects are attempted; a single failure exits `2`.

## How a "project" is discovered (the new capability)

`docs` only knows libraries (`ng-package.json`). `inventory` must also find
**applications**, so it adds `WorkspaceProjectLocator`, which merges four
sources (deduped by project directory, sorted by name for determinism):

1. **`angular.json`** — the Angular CLI manifest. Each entry under `projects`
   yields `(name, projectType, root, sourceRoot)`. Object-valued entries are
   read directly; string-valued entries (Nx-style index) resolve to a
   `project.json` in that directory.
2. **`project.json`** — Nx project descriptors not already seen. An explicit
   workspace-root-relative `sourceRoot` is honored when present and pointing at
   a real directory, otherwise it falls back to `<projectDir>/src`.
3. **`ng-package.json`** — libraries not already covered (reuses
   `ManifestReader` to resolve the entry-file directory as the scan root).
4. **Single-target fallback** — if nothing above matched, treat `--project`
   itself as one project: an application rooted at `<root>/src` if that exists,
   else `<root>`.

`node_modules` and `dist` are always skipped. Projects whose name ends with
`-e2e` are skipped (they are test harnesses).

## What gets walked (`InventoryWalker`)

All `*.ts` under a project's source root, **excluding**: `*.spec.ts`,
`*.stories.ts`, `*.e2e-spec.ts`/`*.e2e.ts`, `*.d.ts`, and anything under a
`node_modules` or `dist` segment. Barrels (`index.ts`, `public-api.ts`) are
walked but contribute nothing because the sidecar only emits real
declarations (re-exports point to objects already inventoried at their
declaration site — no double counting). Results sorted by `Ordinal` relative
path.

## Sidecar — new `inventory(file)` method

Mirrors `document` but walks **every** top-level declaration, not just
exported ones, and adds a `role`/`exported` field. Reuses `jsdoc`,
`collapse`, `hasExportModifier`, the `InjectionToken` detection, and the
deprecation parse already present.

Each item: `{ name, kind, role, exported, doc, deprecated, deprecationReason, file }`

- **kind** — TS syntactic kind: `class`, `interface`, `enum`, `type`,
  `function`, `const`/`let`/`var`.
- **role** — semantic category, resolved in priority order:
  1. decorator `@Component`/`@Directive`/`@Pipe`/`@NgModule` →
     Component/Directive/Pipe/NgModule;
  2. class heritage / functional type `CanActivate(Fn)` etc. → Guard,
     `Resolve(Fn)` → Resolver, `HttpInterceptor(Fn)` → Interceptor;
  3. `@Injectable` → Service;
  4. `new InjectionToken<T>()` → Injection Token;
  5. otherwise a friendly name for the kind (Class, Interface, Enum,
     Type Alias, Function, Constant).

  Heritage/functional guard roles outrank `@Injectable` so an
  `@Injectable() class AuthGuard implements CanActivate` is a **Guard**.

## Output shape (`InventoryRenderer`)

Per project `INVENTORY.md`:

```md
# my-app — Inventory

> Generated by SurfaceQ. Do not edit by hand; regenerate with `surfaceq inventory`.

_Type: application_

## Summary

42 objects (35 exported, 7 internal).

| Category | Count |
| --- | --- |
| Components | 8 |
| Services | 5 |
| Interfaces | 12 |
| … | … |

## Components

| Name | Kind | Exported | File | Description |
| --- | --- | --- | --- | --- |
| `AppComponent` | `class` | yes | `src/app/app.component.ts` | Root component. |
```

- One `##` section per non-empty category, in a fixed order
  (Components, Directives, Pipes, Services, NgModules, Guards, Resolvers,
  Interceptors, Classes, Interfaces, Enums, Type Aliases, Functions,
  Constants, Injection Tokens).
- Within a section, rows sorted by name then file (Ordinal).
- File paths are **project-relative POSIX** (host relativizes; renderer stays
  pure). Pipes escaped; LF endings; single trailing newline. Empty project →
  `_No developer-authored objects found._`.

## ATDD slices (test-first)

1. **Sidecar inventory** — exported+internal coverage, kinds, Angular roles
   (decorator, heritage, functional, token). `SidecarInventoryTests` (L2-033).
2. **Project discovery** — apps via `angular.json`, libs via `ng-package.json`,
   Nx `project.json`, fallback, node_modules/dist/e2e exclusion.
   `WorkspaceProjectLocatorTests` (L2-032).
3. **Renderer** — summary + sections + columns, determinism, pipe-safety,
   empty. `InventoryRendererTests` (L2-034).
4. **CLI end-to-end** — workspace with an app and a lib, one `INVENTORY.md`
   each, `--output`, exit codes, two-run determinism.
   `InventoryCommandTests` (L2-031).
5. **Docs + release** — L2-031..034, README, CLAUDE.md, version `0.12.0`.

## Out of scope (v1)

- Listing class/interface members (that is `docs`' job; inventory is a census).
- Reachability/usage analysis or dead-code detection.
- Templates, styles, and HTML — "objects" means code declarations.
- A single workspace-wide roll-up file (chosen layout is one file per project).
